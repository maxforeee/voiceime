# Project Review Summary

## Top Issues

1. **Production API key embedded in `BuildConfig` via unescaped `buildConfigField`** (`app/build.gradle.kts`). The raw key is written into generated Java source with no escaping/encoding, so `$` or other characters get mangled, and more seriously a secret ends up compiled into the APK. Combined with the missing `networkSecurityConfig` note in `AndroidManifest.xml`, credentials handling is the highest-impact concern. Move the key out of source (local properties / signing config / backend) and read it at runtime.

2. **Cross-thread state races in the voice pipeline.** A cluster of unsynchronized mutable fields spans the ASR stack:
   - `DoubaoAsrClient.kt`: `seq`, `finalReceived`, `ws`, `stopped` accessed from audio-capture, OkHttp reader, and main threads without synchronization.
   - `AudioCapture.kt`: `record`/`thread` fields have no memory visibility guarantee between `start()`, the capture thread, and `stop()`.
   - `GoogleSuggestions.kt` and `ClipboardHistory.kt`: `pending` / `items` mutated from multiple threads without `@Volatile` or locking, with concurrent `ArrayList` iteration risk in `all()`.
   
   These are the most likely source of intermittent production crashes and stale-result bugs.

3. **Resource leaks around the mic and network clients.**
   - `VoiceImeService.onDestroy` never stops an active session, so `AudioCapture` keeps the `AudioRecord` open if the IME dies mid-recording.
   - `DoubaoAsrClient` creates a new OkHttp `client` per session and never shuts it down, leaking dispatcher/connection-pool threads per voice session.
   - On error frames in `onMessage`, the socket is neither closed nor `onClosed` emitted, leaking the WebSocket until GC.
   - In `sendAudio`, a `false` return from `WebSocket.send` is ignored, silently dropping audio (including the final packet).

4. **`Lexicon.kt` database access is unsafe on two fronts.** (a) `readKey` decodes varints/weights with no bounds checks; a truncated/corrupt blob loops past `blob.size` or throws AIOOBE inside the hot lookup path. (b) The asset copy writes directly to the final path with only a `!dbFile.exists()` guard, so an interrupted copy leaves a permanently broken DB that never re-copies, and schema-version failures aren't recovered from. This is the persisted-data integrity risk for the whole input method.

5. **State-machine desynchronization in `VoiceImeService`.** Multiple comments describe the same failure mode: guards and cleanup don't cover all transitions.
   - `failSession()` doesn't clear `lastInterim`, so a later `stopVoiceSession(salvage=true)` commits stale interim text.
   - `switchToKeyboard()`/`closeClipboardPanel()` tear down the session but leave the voice status/interim un-cleared.
   - `onAsrClosed()`/`onAsrFinal()` mutate the voice view without confirming it's still in VOICE mode, and the `sessionId` guard can be bypassed after a mode switch.
   - `stopRecording()` sends the terminal packet through a possibly-null/closed `asrClient`, stranding `PROCESSING` until the 8 s timeout.

6. **`AsrProtocol.kt` frame parsing robustness.** In the error branch `isLast` is hardcoded `false` (a terminating error frame won't terminate), `seq` isn't parsed, and there is no upper bound on payload size before copy/allocation — a malformed/compressed payload can drive unbounded allocation. `optString("text", null)` also returns the literal `"null"` in some org.json implementations.

7. **`method.xml` contains invalid IME-subtype attributes** that AAPT won't accept as intended: `android:overridesImplicitlyEnabledSubtype` and `android:isAuxiliary` are not valid on `<subtype>`, and `android:imeSubtypeLocale` is missing entirely — meaning the subtype may not even register in the system IME switcher.

8. **`VoiceKeyboardView` touch handling is fragile.** `downPending`/`holdActive` are never reset when recording is stopped externally (`resetVoiceUi()`), leaving the view in a stuck state; `removeCallbacksAndMessages(null)` on `ACTION_UP` cancels *all* handler messages; and a pending long-press runnable can fire after detach against a torn-down service.

## Module Hotspots

- **`app/src/main/java/com/voiceime/asr/`** — highest severity density. `AudioCapture.kt` (thread-safety + leak), `DoubaoAsrClient.kt` (5 comments: races, leaked socket/client, dropped sends), `AsrProtocol.kt` (parse robustness). This is the core path and deserves the most review attention.
- **`app/src/main/java/com/voiceime/VoiceImeService.kt`** — 7 comments, all state/lifecycle cleanup gaps. The class is the central coordinator and clearly carries too many responsibilities.
- **`app/src/main/java/com/voiceime/lexicon/Lexicon.kt`** — 6 comments covering DB integrity, O(N²) candidate expansion, per-keystroke synchronous I/O, and unbounded SQL placeholder lists.
- **`app/src/main/java/com/voiceime/online/GoogleSuggestions.kt`** — 5 comments, nearly all concurrency/callback-threading (main-thread contract leak, `pending` visibility, unchecked `URLEncoder` exception).
- **`app/src/main/res/`** (`xml/method.xml`, `values/colors.xml`, `drawable/*`, `values/strings.xml`) — small but multiple correctness/theme issues concentrated here.

## Cross-Cutting Concerns

- **Shared mutable state without synchronization.** Recurring pattern across `DoubaoAsrClient.kt`, `AudioCapture.kt`, `GoogleSuggestions.kt`, `ClipboardHistory.kt`. Adopt a consistent convention (e.g. all client/view state confined to a single thread, or `@Volatile`/`synchronized` on cross-thread fields). `CoroutineScope`/structured concurrency would consolidate much of this.
- **UI-facing callbacks invoked off the main thread.** `GoogleSuggestions.onResult` is called from OkHttp's dispatcher; the `DoubaoAsrClient` `onFinal`/`onInterim` flow to `VoiceImeService` interacts with UI fields. There is no enforced main-thread contract at these boundaries.
- **Lifecycle cleanup not invoked on teardown.** The same pattern (start/subscribe without a matching stop/release) appears in `onDestroy`, the error path of `onMessage`, and `AudioCapture`'s exception handler. A single `close()`/`cleanupSession()` that is guaranteed to run would fix several findings.
- **`optString(...)` JSON-null footgun.** Repeated in `AsrProtocol.kt` and `GoogleSuggestions.kt`: missing `isNull()` checks yield the literal `"null"` as data. Standardize on a safe JSON-string accessor.
- **`apply()` vs durability and main-thread JSON rebuilds.** `ClipboardHistory.add()` and `Lexicon.rememberTap()` both rewrite small prefs blobs with async `apply()` and no bounding/concurrency discipline — a shared pattern worth consolidating into a small persistence helper.
- **Unbounded inputs trusted at boundaries.** `ClipboardHistory` load, `ClipboardPanelView.render`, `Lexicon` candidate expansion, and `AsrProtocol` payload size all assume data was already capped. Defensive clamping at entry points is missing throughout.
- **No dark-theme / night resources.** `colors.xml` is light-only; `Theme.Translucent.NoTitleBar` with no `values-night` means the IME ignores system dark mode. Hardcoded `android:tint` on the mic vectors compounds this and blocks theme-aware coloring.

## Quick Wins

- **`Lexicon.readKey`**: add explicit `pos + len <= blob.size` / bounds guards before decode — a few lines removes the corrupt-DB crash and stale-read loop.
- **`AsrProtocol` error branch**: parse `seq`, honor `isLast`, and add a max-payload-size constant before copy. Small, contained, closes a DoS/liveness gap.
- **`DoubaoAsrClient.sendAudio`**: check the `WebSocket.send` boolean and route failures to `onError`; remove the redundant `if (stopped && !last)`.
- **`GoogleSuggestions`**: clear `pending` (identity-guarded) on completion/failure, mark it `@Volatile`, wrap `URLEncoder.encode` with `StandardCharsets.UTF_8` (no checked exception), and post `onResult` to the main thread.
- **`ClipboardHistory`**: cap the list during `load()`, and wrap `add`/`clear`/`all` in `synchronized` (or use a `CopyOnWriteArrayList`).
- **`VoiceKeyboardView`**: reset `downPending`/`holdActive` when recording is stopped externally; replace `removeCallbacksAndMessages(null)` with `removeCallbacks(longPressRunnable)`; `removeCallbacks` in `onDetachedFromWindow`. Also drop the dead `holdMode` field.
- **`method.xml`**: remove the invalid `overridesImplicitlyEnabledSubtype` and `isAuxiliary` attributes and add `android:imeSubtypeLocale` — otherwise the subtype may not register.
- **`strings.xml`**: convert the clipboard title to a `%1$d`-formatted resource so the "10" tracks the code limit.
- **`T9KeyboardView`**: delete the trivial `textKey` wrapper; reconcile the `"1"` key's code-vs-label mismatch between `digitKey` and `VoiceImeService.onKey`.
- **`build.gradle.kts`**: stop reading `System.getenv` in `defaultConfig` (configuration-cache hazard) and add a `debug { applicationIdSuffix = ".debug" }` so debug/release don't share an `applicationId`.
