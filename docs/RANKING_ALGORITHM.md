# VoiceIME 排序与组合算法（v1.3.0，自研）

九键的边界是模糊的：一个按键串能对应很多字母组合，一串拼音能切出很多
种音节。所以排序不能只靠一个权重数字，必须是一套能说清楚的规则：
**先合法，再常用，再学过**。下面中文、英文各一套，规则写在代码里
（`lexicon/Lexicon.kt`、`lexicon/EnglishLexicon.kt`），这里是同一套规则
的文字版。

## 通用原则

1. **合法优先**：只有能合法组合出来的东西才能上屏。中文是合法拼音音节，
   英文是词库里真实存在的单词。解不出来的输入绝不输出数字键码。
2. **常用优先**：词频高的排前面。词频来自公开语料（中文是字幕词频
   zh_full + 雾凇词频 + jieba 计数；英文是 wordfreq Zipf 估计值），
   不是人工拍脑袋。
3. **学过优先**：用户以前选过的词（`learned.db`，只存本地）永远排在同档
   的最前面，选得越多越靠前。学过的词是用户自己的，比任何公开词频都准。
4. **本地不硬猜**：本地只纠“根本拼不出来”的东西；合法但可能错的
   （比如 hou 和 hao 都是合法音节），本地不动，等 AI 看上下文。

## 中文：合法音节分词 + 词频 + 学过优先

输入是一串数字键码（比如 64426 = nihao 的按键）。

1. **枚举切分**：按声母+韵母把数字串切成音节。切分时只认 424 个合法
   拼音音节表里的音节（声母+韵母，或独立成音节的韵母，如 a、o、e）。
   枚举时先试长的音节（6 位数字的块先试，再试短的），这样最长合法
   音节先被找到。
2. **排切分**：切分结果先按**段数从少到多**排（段越少，音节越长、越
   完整——ni hao 两段，排在 ni ha o 三段前面），段数相同的按它能出的
   最好那个词的分数排。默认第一种切分就是对的；其他切分留在倒三角
   下拉框里备选。
3. **找词**：每个切分（拼成拼音串，如 nihao）去词库里查词。一个拼音串
   能出的词按分数排，分数 = 词频 + 词典权重：
   - 词频分：`log10(语料计数)`，计数越大分越高。取对数是因为词频是
     数量级差别（“的”出现几千万次，“饕餮”出现几次），直接比数字会
     让高频词永远赢，取对数后差距变合理。
   - 词典权重：词典自带的权重（明月拼音的百分比、雾凇的归一化权重），
     同词频时权重高的在前。
   - 学过的词：在分数上加一个很大的加分（选过 1 次就加，选得越多
     加得越多，上限 8 次），保证学过的词一定排在没学过的前面。
4. **去重取前 50**：所有切分的词合在一起，按分数排，去重，取前 50 个
   上候选栏。第一候选就是空格/回车默认上屏的那个。
5. **前缀联想**：输入还没打完时（比如只打了 64），词库的前缀索引会补
   几个以这个前缀开头的高频词，方便少打几个键。

## 英文：字母组合枚举 + 单词实用度

输入是一串数字键码（比如 4663），外加用户在下拉框里定住的字母。

1. **枚举组合**：每个按键对应 3–4 个字母（2=abc，3=def……），数字串
   就是一组字母组合。先按数字串在“数字前缀树”里找：树是按词频表
   建的，每个节点存着以这个数字前缀开头、最常用的 30 个词。
   比如按 4，节点里是所有 g/h/i 开头的最常用词；再按 6，节点缩到
   [ghi][mno] 开头的词。
2. **定住的字母是过滤条件**：用户在下拉框里点了一个字母（比如按 4
   后点了 G），这个位置就锁定成 G，之后只留这个位置是 G 的词。
   没定住的位置继续按数字串枚举。锁定的字母越多，候选越准。
3. **排单词**：候选词按三档排，档内按词频：
   - 第一档：学过的词（`learned.db` 里有的，按选过次数排）；
   - 第二档：常用词（wordfreq 前 1 万词 + 专有名词，按 Zipf 频率排）；
   - 第三档：不常用词（37 万词全表，按 Zipf 频率排，没有频率的按
     字母顺序），跟常用词之间隔一个分隔行，绝不混在一起。
   每档内部都是“越常用越靠前”，三档之间是“学过 > 常用 > 不常用”，
   所以每一步为什么排前面都能说清楚。
4. **上屏**：点一个词就上屏，自动加一个空格（跟 T9 一样）。空格键
   上屏第一个候选词；没有候选词时，空格上屏已定住的字母（用户亲手
   定的字母一定是对的）；字母也没定住、词也没有，那就什么都不上屏
   （绝不输出数字）。
5. **大写**：句首自动大写（开头、句号/感叹号/问号 + 空格之后的首字
   母大写），其余小写。大写只在提交那一刻算，不影响候选排序。

## 本地纠错（只纠拼不出来的，把握大才纠）

触发条件：当前输入**没有任何合法解**（中文切不出合法音节、或切出来
没有词；英文数字串没有任何候选词）。只要有一个合法解，本地就不动。

- 中文：对数字串做一次“一位编辑”（改一位数字、插一位数字、删一位
  数字），找出能切出合法音节、且有高频词的改法。要求改完的最好那个
  词是常用词（词频够高），并且明显比第二好的改法强（分数至少 3 倍，
  或只有一种改法）。上下文加分：如果前一个已打出的字 + 纠过来的音节
  能拼成词库里的常用词（比如“你”+ hao = “你好”），直接定下来。
  不满足就什么都不改，留给 AI 或用户自己删。
- 英文：对数字串的每一位试相邻键替换（九宫格里上下左右挨着的键，
  比如 4 的邻键是 1、2、5、7、8），找出能拼出常用词的替换。要求纠
  出来的词是常用词（前 3000 词），否则不动。
- 计算在后台线程做，不堵打字；算完先核对输入没变过才应用（输入变
  了就丢弃这次结果）。

## AI 纠错（本地把握不够时才走）

本地纠不了、或合法但语义可疑时，走后端 DeepSeek（`/typo` 接口）。
触发克制：只在词边界清楚、上下文够了的时候才问（打完一个词后停顿
约 1 秒，或用户按空格/回车提交时）；防抖（每次停顿最多问一次）；
同一句话不重复问；没网时只走本地。AI 的结果只当候选出现，绝不强行
替换。AI 判断时看“前面的字 + 可疑的词 + 后面的字”一起看，比如后
面跟了“面”就是“你后面”，不要动；后面没东西、整句是问候，才是
“你好”。

## 词库（我们的资产）

- 内置核心词库（`assets/`，没网时兜底）：中文 `lexicon.db`（明月拼音
  + 雾凇 base + jieba + 自建专有名词，138,340 词）；英文
  `english_words.txt`（wordfreq 前 1 万 + 专有名词，10,947 词）+
  `english_words_rare.txt`（37 万词全表，按数字签名排过序）。
- 云端词库（`lexicons/`，16 个文件，3,063,313 条）：联网时按
  `manifest.json` 从 GitHub Raw 拉，在后台建索引进
  `cloud_lexicon.db`，没网时用内置的。云端只补内置没有的词（去重后
  才入库），加载顺序 common → frequency → proper，同词取最高词频。
- 自建专有名词：AI 三巨头 OpenAI、Google/谷歌、Anthropic 都在，
  另加 Microsoft/微软、Meta、xAI、DeepMind 等约 50 个 AI 公司/品牌，
  以及常见公司、品牌、地名、人名。以后用户说加什么名字就加什么。
